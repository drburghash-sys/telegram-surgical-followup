# متابعة العمليات — Telegram Mini App + Bot

نسخة تجريبية ببيانات وهمية. لوحة الإدارة باللغة العربية تفتح من قائمة البوت داخل تيليجرام، وتظهر للمدير المسجل فقط. المرضى الوهميون يستخدمون رسائل البوت وأزرار **نعم/لا**. كل الملفات في مشروع واحد يعمل على **Cloudflare Workers + D1**، ويحفظ كوده في **GitHub**.

> **الحالة:** نُشر Cloudflare Worker على `https://surgical-followup-demo.drburghash.workers.dev` وأُنشئت جداول D1. تفعيل بوت `@burghashbot` وقائمة الإدارة يعتمد على حفظ `TELEGRAM_BOT_TOKEN` و`ADMIN_TELEGRAM_ID` ضمن أسرار GitHub Actions ونجاح إجراء النشر اللاحق. المعاينة في المتصفح تعرض بيانات وهمية بدون حفظ. لا ترفع توكن بوت أو بيانات حقيقية إلى ملفات GitHub.

## الوظائف المطبقة

- ملف مريض برقم داخلي عشوائي، وحقول إدارية قابلة للتخصيص، ولغة عربية/إنجليزية.
- رابط تفعيل فردي يصدر مرة واحدة مع QR؛ التفعيل معلق حتى موافقة المدير، ويمكن طلب تغيير/استعادة الحساب من `/change` أو `/recover P-XXXXXX`. رمز الاستعادة الجديدة يصدره المدير من الملف.
- قائمة جاهزة لمتطلبات ما قبل العملية، إضافة متطلبات مخصصة، حفظها وإرسال الجديد فقط يدويًا، وردود نعم/لا قابلة للتغيير، ومراجعة/إعادة/إلغاء وإشعارات يدوية.
- موعد توقيع وعملية لكل ملف، معاينة تعديل قبل إعادة الإرسال، إبطال التأكيد القديم عند نجاح إرسال التعديل، نقل الموعد إلى مريض آخر وإشعار الأول بالتأجيل، تعليمات منفصلة وإقرار اطلاع.
- رسائل عامة ونماذج عربية/إنجليزية قابلة للتعديل، وصلاحيات إدارة مرتبطة بـ Telegram `initData` الموقّع ومعرّف المدير.
- تنبيهات للمدير عند تغيير إجابات المرضى، تذكيران ١٢/٢٤ ساعة للمواعيد البعيدة، وعند ثلث/ثلثي المدة للمواعيد الأقرب (توقيت مكة)، تذكيران عند عدم الإقرار بالتعليمات؛ إعادة محاولة عند فشل إرسال البوت.
- قائمة نشطين وأرشيف، إعادة تنشيط خلال ٧ أيام، ثم حذف من قاعدة بيانات التطبيق مع المهام والإجابات واللقطات اليومية المرتبطة.
- لقطة تلقائية يومية لكل ملف نشط في D1 (استعادة الحقول الإدارية فقط من واجهة التطبيق)، وتصدير JSON يدوي لكل قاعدة المرضى الحالية. توفر D1 أيضًا Point-in-Time Recovery ضمن حدود الخدمة.
- شاشة معاينة مستقلة تعرض أمثلة وهمية دون أي حساب أو تسجيل.

## الإعداد لأول مرة

### ١. البوت

1. افتح `@BotFather` في تيليجرام وأنشئ بوتًا باستخدام `/newbot`.
2. احتفظ برمز البوت (`TELEGRAM_BOT_TOKEN`) **خارج GitHub**.
3. أرسل `/start` إلى البوت من حساب المدير.
4. لمعرفة رقم حساب المدير عبر واجهة Bot API، من حاسوب عليه Node 22 شغّل `TELEGRAM_BOT_TOKEN=... node scripts/get-my-id.mjs` قبل تفعيل webhook. أو أرسل `/id` للبوت بعد نشر الكود ومعاودة تشغيله.
5. اسم البوت المعتمد لهذا المشروع هو **@burghashbot**، وهو مثبت في `wrangler.jsonc` كمتغير عام `BOT_USERNAME`، فلا حاجة لإضافته ضمن الأسرار.

### ٢. Cloudflare D1 وWorkers

1. أنشئ حساب Cloudflare مجانيًا، وثبّت Node.js 22 على حاسوب أو استخدم بيئة نشر GitHub/Cloudflare تدعم بناء Workers.
2. من داخل مجلد المشروع: `npm install` ثم `npx wrangler login`.
3. أنشئ قاعدة البيانات: `npx wrangler d1 create surgical_followup`.
4. انسخ المعرّف الذي سيظهر إلى `database_id` في `wrangler.jsonc` بدل `REPLACE_WITH_YOUR_D1_DATABASE_ID`.
5. أنشئ الجداول: `npm run db:remote`.
6. أضف أسرار التشغيل الثلاثة (سيطلب كل أمر قيمته دون إظهارها في الكود). اسم البوت `burghashbot` مُدرج مسبقًا في إعدادات المشروع:
   ```sh
   npx wrangler secret put TELEGRAM_BOT_TOKEN
   npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
   npx wrangler secret put ADMIN_TELEGRAM_ID
   ```
   أنشئ secret عشوائيًا جديدًا لـ `TELEGRAM_WEBHOOK_SECRET` يضم الحروف والأرقام و`_` و`-`، ولا تشاركه.
7. انشر: `npm run deploy`، ثم انسخ رابط `https://...workers.dev`.
8. اضبط متغيرات البيئة الأربعة نفسها محليًا، وأضف `WORKER_URL=https://...workers.dev` ثم شغّل `npm run setup:telegram` لتسجيل webhook وضبط زر قائمة الإدارة.
9. افتح تيليجرام في حساب المدير واضغط **Menu → لوحة إدارة العمليات**. استخدم بيانات وهمية فقط.

### ٣. GitHub

1. أنشئ مستودعًا **جديدًا ومنفصلًا**؛ لا تضع الملفات داخل مشروعك الجراحي السابق.
2. ارفع الملفات بعد تعديل `wrangler.jsonc` بإعدادات قاعدة بياناتك. لا ترفع `.dev.vars` أو tokens (الملف مستثنى في `.gitignore`).
3. يمكن ربط المستودع بخدمة Workers لاستخدام النشر التلقائي من GitHub، أو النشر يدويًا عبر Wrangler.

## اختبار محلي

```sh
npm install
npm test
npm run db:local
npm run dev
```

لفتح المعاينة المستقلة دون البوت، افتح `preview-demo.html` في المتصفح. عند فتح `/` في المتصفح العادي وليس من تيليجرام تظهر أيضًا معاينة ببيانات وهمية فقط، بلا إمكانية حفظ.

## قواعد مهمة في التطبيق

- **لا توجد محادثة حرة في لوحة الإدارة.** يستطيع المريض تقنيًا إرسال نصوص للبوت، لكنه يتجاهلها ولا يضعها في قاعدة التطبيق. تيليجرام نفسه قد يحتفظ بالرسالة وفق سياساته.
- **الرد بنعم على المتطلب إفادة من المريض فقط**، ويحتاج المتطلب إلى اعتماد المدير بعد مراجعته. تأكيد الموعد ليس موافقة جراحية مستنيرة.
- **عند نقل موعد:** ينتقل الموعد إلى ملف البديل كمسودة، ويُغلق القديم ويُخطر المريض الأول بالتأجيل.
- **التذكيرات:** العامل المجدول يعمل كل دقيقة تقريبًا؛ قد تصل الرسائل متأخرة بسبب البنية التحتية. في الأعطال الملتبسة (نجاح إرسال Telegram مع انقطاع قبل تثبيت حالة قاعدة البيانات) لا يمكن ضمان عدم التكرار بنسبة ١٠٠٪ من دون آلية تسوية إضافية.
- **الباركود:** يبقى صالحًا حتى الموافقة على التفعيل أو الإلغاء اليدوي، ولا يثبت وحده هوية من حصل عليه. تحتاج موافقة الإدارة.
- **الحذف:** يبدأ من لحظة الأرشفة، ويُنفّذ في أول مهمة مجدولة مناسبة بعد انقضاء ٧ أيام. يُحذف من القاعدة النشطة واللقطات المرتبطة به، لكن الاستعادة الزمنية الخاصة بمزود التخزين والنسخ المصدرة يدويًا ليست خاضعة لنفس الحذف الفوري. كما أن رسائل تيليجرام القديمة قد تظل في المحادثة.
- **استعادة النسخ من الواجهة:** لاسترجاع **حقول الملف الإدارية فقط** من اللقطات اليومية، ولا تعيد أحداثًا قديمة أو رسائل أو مواعيد كان يمكن أن تكون انتهت. الاستعادة الكاملة لقاعدة بيانات D1 تُدار من Cloudflare.
- **واجهات Mini App:** تحقق الخادم من توقيع Telegram `initData` وصلاحية المدير. لا تعتمد الصلاحيات على بيانات JavaScript فقط.

## أين ملفات المشروع؟

- `src/worker.js` — المسارات، قواعد التخزين، webhook، المجدول.
- `src/telegram.js` — التحقق من توقيع Telegram والإرسال والأزرار.
- `src/rules.js` — قواعد المواعيد والتذكيرات.
- `migrations/0001_init.sql` — جداول D1 والبيانات الافتراضية للقوائم.
- `public/index.html`, `public/app.js`, `public/style.css` — لوحة Mini App.
- `scripts/setup-bot.mjs` — ربط Bot API وفتح قائمة الإدارة.
- `tests/` — اختبارات للوقت والتوقيع ومبادئ صلاحية الرد.

## حدود النسخة الحالية

هذه **نسخة تجريبية عملية تحتاج نشرًا وربطًا قبل التشغيل الحي**. لم يُجر اختبار Telegram API في حساب حقيقي أو اختبار نشر Cloudflare من بيئتك. يظهر QR داخل اللوحة باستخدام مكتبة JavaScript محمّلة من CDN؛ إذا تعذر تحميلها يظل رابط التفعيل متاحًا للنسخ. نسخة الموقع التجريبية لا تحفظ أي بيانات.
